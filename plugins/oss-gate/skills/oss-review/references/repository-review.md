# Local repository dependency review

Use this path when the user requests a whole-repository dependency review. The implementation supports Yarn Berry/Cargo locks, Go declarations, Java/Kotlin resolved inputs, Swift pins and imported container image scans. It does not clone URLs, install dependencies, run build scripts or scan source-code vulnerabilities. Python and other unsupported formats remain coverage gaps. Do not substitute a published package's deps.dev graph for the local dependency inventory.

Resolve `<plugin-root>` from this skill's directory (`../..`). Prefix CLI commands with:

```sh
uv run --frozen --project "<plugin-root>" python "<plugin-root>/cli.py"
```

1. Run `repo-plan <absolute-local-repository> --output-root <absolute-output>` or the MCP `plan_repository` tool, according to the installation's transport reference. This is offline. Read the returned projects, ecosystem-qualified locked/declared package identities, file hashes, excluded directories and gaps. The collector repeats discovery; do not modify inputs between planning and collection.
2. Container-only collection with a valid imported scan is offline and does not require the public flag. Mixed repositories follow the same public-identifier restrictions as other package queries. Send only identifiers known to be public. For a repository whose package identifiers are confirmed public, use `repo-collect <directory> --public-packages --output-root <directory> --language ko|en|both`, or MCP `collect_repository(..., public_packages=True)`. If an explicit launch-selected policy has an identifier allowlist, omit the public flag and only permitted names are queried. Never infer public status from an `npm:` locator, a Go module path, a registry source or a public root repository. Do not weaken the policy or query a registry to discover whether a private name is public. If the available context cannot establish which identifiers may be sent, present the concrete local plan and ask for the missing scope.
3. Read sealed `data.json` and `api-responses.json`. CLI collection generates deterministic bilingual or single-language reports automatically. After MCP collection, run `repo-render <saved-folder> --language ko|en|both` through the locked CLI. Rendering verifies evidence hashes and does not contact services. Repository reports use `oss-gate.repository-review/1` and `oss-gate.repository-policy/1`; existing package render/reassess/portfolio commands do not accept them.
4. Return the scoped verdict, project count, query coverage, key blockers, material unsupported files and report paths. This is a declared/locked dependency vulnerability/license screening, not a maintenance review or a declaration that the deployed application is safe. Explain that coverage denominators contain identified ecosystem/name/version tuples only. A global advisory count deduplicates aliases; affected package counts remain separate.

The default query cap is 2,000 unique package versions (`--max-packages` accepts 1..10000). Advisory details are capped at 1,000. OSV pagination has per-query and per-run bounds. Every cap leaves incomplete evidence. Custom sources, patches, unresolved peer bindings and manifest/lock mismatches cannot yield a complete allow verdict. Original locators for unsupported sources are represented by hashes rather than copied credential-bearing URLs.

Collection writes a new unique run. Rendering regenerates `review.<language>.md` and `report.<language>.html` from that snapshot; place any separately requested editorial narrative in a different file. Do not edit sealed evidence. Recollect into a new run when the user requests refreshed findings.

## Go and Cargo scope

- Go: parse `go.mod` requirements, indirect annotations, versioned module replacements, exclusions and `go.work` members/overrides. Local replacements are hashed and remain unverified. Conflicting or unreadable workspace replacements suppress uncertain queries. `go.sum` and `go.work.sum` are checksum evidence only; never count their historical entries as installed dependencies. Requirements are declared versions, not the selected build list or the complete transitive graph. Every Go project retains `go_build_list_unverified` and cannot receive an overall allow verdict. Do not execute Go commands to fill that gap without a separately authorized workflow.
- Cargo: parse lock format versions 3 and 4 with `Cargo.toml` workspaces, aliases, inherited dependencies/versions, in-tree path members and target/build/dev/optional declarations. Query only recognized crates.io source identities. Git, alternate registries, patches/replacements and unresolved local nodes remain gaps. Recognized `.cargo/config` and `.cargo/config.toml` files also remain configuration gaps; external configuration is outside the inventory. Match common caret/tilde/wildcard/exact/comparison requirements; prerelease or unsupported syntax remains unverified. This is the all-target lock inventory, not a feature-selected build graph.
- Deduplicate by ecosystem, name and version. Reports label Go versions as declared, Maven trees as resolved, and npm/Cargo/Gradle/Swift entries as locked. Root-project/local code licenses and reachability are not assessed.


## Java/Kotlin and Swift inputs

- JVM coordinates use the Maven ecosystem for both Java and Kotlin. Import a Maven Dependency Plugin JSON tree as `dependency-tree.json` beside each module's `pom.xml`. The exported root must match the POM when its identity is literal. Preserve scopes, classifier/type and tree edges; exclude verbose nodes marked `included: "false"`. Dynamic/SNAPSHOT dependencies, system-path artifacts and unverified variants/configuration remain gaps. Do not infer versions from dependency ranges in POMs or execute Maven to resolve them automatically.
- Read Gradle `gradle.lockfile`, `buildscript-gradle.lockfile` and legacy `gradle/dependency-locks/*.lockfile` with adjacent `build.gradle[.kts]`. Configurations remain attached to occurrences. Locks do not establish direct/transitive edges, enabled profiles, custom repositories or freshness. Build scripts and settings are never executed.
- Swift reads `Package.resolved` schema 1/2/3, including nested Xcode locations, and queries OSV's `SwiftURL` ecosystem with canonical `host/owner/repository` names and exact semantic versions. Input HTTPS schemes and `.git` suffixes are stripped; policy identifiers use `swift:github.com/owner/repository`. Advisories recorded under ambiguous short-name aliases may not match and remain an explicit gap. Registry/local sources and branch/revision-only pins remain unresolved. `Package.swift`, mirrors and dependency edges are not evaluated. deps.dev does not supply Swift license metadata here; unknown licenses remain a hold under the existing classifier. Never describe an empty OSV result as Swift adoption approval.

## Container imports

- Discover `Dockerfile`, `Dockerfile.*`, Compose image references, `trivy.json`, `*.trivy.json`, `grype.json` and `*.grype.json`. Read native Trivy schema 2 container-image JSON and Grype image JSON only. SBOM, filesystem and text reports are unsupported. Exports must be outside excluded directories such as `build`, `target` and `dist`.
- Import reports the user supplies or produces in an independently authorized image-scanning workflow. The collector does not pull/build/run images, invoke scanners or query Docker Hub/Scout. Docker Scout is a separate SBOM/vulnerability service, not a universal public vulnerability API used by this adapter.
- Bind declarations to scans only through matching canonical repository names plus SHA-256 manifest digests from `RepoDigests`/`repoDigests`. Tags and image configuration IDs cannot establish that match. Variable interpolation and unsupported Compose features remain gaps; a base-image scan never establishes final-image coverage.
- Retain native suppressed/ignored findings in the verdict. High/critical severity or CVSS >= 7 yields hold. Unknown severity, zero findings, filtering, scanner/database freshness and incomplete inventories do not establish allow. Apply license restrictions and additional review rules to imported component records too. `container:<namespace>:<name>` identifiers remain local and are never sent to a registry.
- Preserve source file SHA-256, image identity, scanner/version/time when supplied, component/license records and normalized findings. Drop raw image environment, descriptions and scanner configuration. Keep the original report separately if it is needed for independent audit; sealed evidence contains its hash and normalized import, not a full copy.
- Report imported scan/finding counts separately from OSV/deps.dev coverage. Findings are per package/version/namespace/advisory, not a global CVE count. No new external service or runtime scanner dependency is introduced.
