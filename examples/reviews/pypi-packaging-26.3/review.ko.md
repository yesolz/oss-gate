# packaging 26.3: Python 도구의 작은 기반 라이브러리

## 판정과 범위

**조회한 패키지 범위에서 OSS Gate 정책/3 기준으로 도입 가능입니다.** 정확한 PyPI 버전의 라이선스를 분류할 수 있었고, 알려진 취약점이 반환되지 않았으며, 일치하는 그래프에 패키지 의존성이 없습니다. Scorecard 신호는 8.8입니다. 해당 고지를 유지하고 프로젝트에서 사용할 API를 테스트하세요.

## 어떤 일을 하나요

Python 버전을 비교하거나 의존성 요구사항을 해석하는 도구를 만들 때, packaging은 각 프로젝트가 파서를 직접 만드는 일을 줄여 줍니다. [공식 문서](https://packaging.pypa.io/en/stable/)는 버전·요구사항·환경 마커·호환성 태그 등을 설명합니다. 이 개요는 공식 문서를 바탕으로 작성했고, 이 예제에서 DeepWiki는 사용하지 않았습니다.

## 라이선스와 의존성

기록된 표현은 `Apache-2.0 OR BSD-2-Clause`입니다. 자동 검토는 허용 가능한 선택지를 고르고 그 근거를 보존합니다. 실제 사용할 라이선스 선택지와 고지는 확인해야 합니다. 반환된 그래프에는 루트 패키지만 있어 직접·간접 패키지 의존성이 모두 0개입니다. Python 설치 환경이나 빌드 도구 전체를 조사했다는 뜻은 아닙니다.

## 취약점과 유지보수

2026-11-22 조회에서는 알려진 권고가 반환되지 않았습니다. 특정 시점의 관찰 결과이며 안전 보장은 아닙니다. Scorecard 종합 점수는 8.8이고 자료 날짜는 2026-08-24입니다. 수집일보다 오래된 신호이며 실시간 유지보수 평가가 아닙니다.

## 도입할 때 할 일

사용할 버전을 고정하고 필요한 API를 테스트하세요. 선택한 라이선스 조건을 유지하고 버전이나 관련 권고가 바뀌면 다시 검토하세요. API 메타데이터로 모든 실행 동작을 확인할 수는 없습니다. 외부 통신을 별도로 조사하지 않았으며 통신이 전혀 없다고 단정하지 않습니다.

## 근거

이 예제는 로컬 정책/3 후보에서 수집했습니다. `data.json`, `api-responses.json`, `evidence-sha256.json`에 정규화 결과·원문 응답·무결성 해시를 보존합니다. 추가 정책이나 수용 기록 없이 가능 판정이 나왔습니다. 자동 판정과 이 설명 문서는 구분됩니다.
